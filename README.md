# ComfyUI Prompt TAG Manager · 汐皮笑脸的提示词管理

> **当前安装包只保留插件本体：`builtin_tags` 内置词库与用户历史 / 缓存均已清空。**
> 打开「汐皮笑脸的随机tag」时词库列表为空，需要自行导入或新建词库；手动提示词框、
> 自然语言框、tag 合并与历史板代码不受影响。

一个纯 tag 向的 ComfyUI 提示词插件，现已整合原来的 **提示词历史**：

* **汐皮笑脸的随机tag**：一级分类 → 二级分类 → 子项三级词库，支持批量导入导出、
  按分类随机抽取、权重语法、中文描述、多套词库切换；
* **汐皮笑脸的tag合并**：把多路提示词按顺序整合成一条，输入口自动增加，也可手动加；
* **汐皮笑脸的tag历史板**：自动保存每次提交用的提示词，支持文字 / 图文列表、选中注入。

功能参照 [WeiLin-Comfyui-Tools](https://github.com/weilin9999/WeiLin-Comfyui-Tools) 的提示词面板思路重写，
**只保留 tag 相关功能，不含 LoRA 加载**；实现上刻意避开了 Vue 构建与 SQLite，
词库就是可直接编辑的 JSON 文件，装进 `custom_nodes` 就能用，不需要任何额外依赖。
WeiLin 导出的 `.sql` 词库也能直接导入（内置的「人物」词库就是这么来的）。

## 一、功能特性

| 分类 | 说明 |
| --- | --- |
| 三级词库 | 一级分类 / 二级分类 / 子项（tag），可自由增删改、重命名、拖拽式浏览 |
| 多路合并 | **汐皮笑脸的tag合并**：`prompt_1`、`prompt_2`… 按顺序拼成一条，接满自动加口，也可点「＋ 增加输入端」手动加；支持分隔符、去重、`\n` 转义 |
| 提示词历史 | **汐皮笑脸的tag历史板**：每次排队自动存一份，文字 / 图文两种列表，支持删除、复制、收藏夹、拖拽排序、导入导出和选中注入 |
| 历史分页 | 记录多时自动分页显示，可选每页 20 / 50 / 100 条；支持首页 / 上一页 / 下一页 / 末页和页码跳转，勾选和批量操作可跨页 |
| 历史交互 | 图文模式默认只看图片（原图完整显示，不裁切），点「显示文字」后图片在左、提示词在右；双击缩略图看大图；双击正文就地编辑，编辑框自适应但限高，长文本内部滚动 |
| 统一分类 | 三个节点都放在节点菜单的 **`提示词管理`** 分类下 |
| 内置词库 | **人物（默认，1612 tag / 28 个二级分类）**、Danbooru 基础（573 tag）、国风古风（244 tag），**全部 2429 个 tag 都带中文翻译** |
| 中文翻译 | 每个 tag 都有中文释义：**直接显示在 tag 后面**（可用「中 已开/已关」开关隐藏），悬停也能看，**搜索中文也能找到英文 tag**（如搜「红发」→ `red_hair`） |
| 批量导入 | 支持 **JSON / CSV / TSV / TXT / SQL**（WeiLin-Comfyui-Tools 导出的 `.sql` 可以直接导入），可覆盖、可合并、可另存为新词库 |
| 批量导出 | 一键导出 **JSON / CSV / TXT**，可按「整个词库 / 当前一级分类 / 当前二级分类 / 仅已选 tag」范围导出，支持下载或复制到剪贴板 |
| 批量编辑 | 单个二级分类可以用「一行一个 tag」的文本域整体编辑，增删一次性完成 |
| 随机抽取 | 每个二级分类可设为「随机池」，设定抽取数量 N，由节点的 `seed` 决定结果，**同种子可复现**；池子只存库/分类引用，**不把上千条候选塞进工作流** |
| 多套词库 | 可无限新建自己的词库并一键切换 |
| 权重语法 | 已选区每个 tag 可单独调权重，默认**不输出权重**；需要时可选 `(tag:1.2)` 或 `tag:1.2`，括号会自动转义 |
| 其他 | 全局搜索（跨分类、支持按分类名/中文描述匹配）、全选 / 反选、顺序自定义、单条停用、下划线转空格、去重、自定义连接符 |
| 排版 | 子项按**从上至下的单列**展示：左边 tag、右边中文翻译（列对齐），斑马纹 + 高对比配色，一眼扫得清 |
| 提示词框 | 面板里带一个**手动提示词框** + 使用方式下拉（仅提示词框 / 仅 TAG 词库 / 两者结合前后），与节点上的同名控件实时双向同步；历史板里选中的记录能直接写进这个框 |
| 自然语言 | 另有**自然语言描述框**（写整句人话，不被空格拆分/去重），可勾选「组合在末尾」，面板里同样有且实时同步 |
| 参数说明 | 所有参数都有**中文悬停提示**，说清作用范围与副作用 |
| 改翻译 | 每行右侧 **✎** 可改单条翻译（双击翻译也可），中栏 **≡** 可批量改 `tag = 中文翻译` |
| 提示词框工具 | 面板里提示词框带 **整理 / 去重 / 删末尾 / 清空** 四个按钮：一键统一连接符、去掉重复段、删掉最后一段 |
| 分段翻译与删除 | 提示词框下面有一条**分段条**：内容切成一段段胶囊，每段显示中文翻译（查当前词库，空格 / 下划线 / `(tag:1.2)` 三种写法都认），点每段的 **✕** 就能删掉这一段；**点译文即可修改并保存到本地** |
| 翻译接口 | 词库里查不到的段可以调翻译接口机翻（**默认 MyMemory，免费无需 Key**），带本地缓存；支持 Google / LibreTranslate / 自定义地址；机翻可一键「保存译文」落到词库或 `.custom_descs.json` |
| 中文界面 | 节点与面板全中文；seed 使用 ComfyUI 自带的「生成后控制」 |

## 二、安装

```bash
cd ComfyUI/custom_nodes
git clone https://github.com/tempstsumaXXX/xxxTag.git ComfyUI-PromptTagManager
# 或者：把 ComfyUI-PromptTagManager 整个文件夹直接复制到 custom_nodes 下
```

重启 ComfyUI。**没有任何 Python 第三方依赖**，前端也不需要构建。

> **升级提示（v2.0）**：提示词历史已经并入本插件，**不要再同时安装 `ComfyUI-PromptHistory`**，
> 否则历史节点和 `/prompt_history` 接口会重复注册。
> 原来的「随机 TAG 提示词（简易版）」节点已经移除；旧工作流里的这个节点会显示缺失，
> 请改用「汐皮笑脸的随机tag」或「汐皮笑脸的tag合并」。

安装成功后：

* 节点菜单：`提示词管理 → 汐皮笑脸的随机tag / 汐皮笑脸的tag合并 / 汐皮笑脸的tag历史板`
* 浏览器控制台会打印 `[PromptTag] 前端扩展已加载`
* 控制台会打印 `[PromptTag] 接口已注册：/prompt_tag/*（词库目录：…）`
* 控制台会打印 `[PromptHistory] 接口已就绪：/prompt_history/list（数据目录：…）`

## 三、快速上手

1. 添加节点 **「汐皮笑脸的随机tag」**。
2. 点节点上的 **🏷 打开Tag词库面板**，会弹出一个可拖拽、可缩放的面板（位置和大小会被记住）。
3. HTTP 接口**默认已开启**，面板直接就能用插件自带的全部词库（人物 1612 tag、
   一键模式 20 万条等）。若被关掉，面板会提示并给一个 **「开启 HTTP 接口」** 按钮（见下节）。
4. 左栏选一级分类 → 中栏选二级分类 → 右栏点 tag 加入「已选」。
5. 想随机？把鼠标移到某个二级分类上，点 **🎲**，它就是一个随机池；在「已选」区用 `＋ / −` 调整抽取数量。
6. 关闭面板，节点上的预览会显示当前提示词；把节点的 **提示词** 输出接到 CLIP Text Encode 即可。

> 面板只是编辑器，**真正的数据保存在节点里**（工作流会带着走）。所以关掉面板、复制节点、切换工作流都不会丢。

### HTTP 接口开关（默认开启）

插件用 ComfyUI 自带的 HTTP 服务对外提供词库读写（不额外监听任何端口），**默认开启**：

* 可以在面板顶部提示条里一键关掉（关掉后只有 `/prompt_tag/status` 与 `/prompt_tag/switch` 可用），
  关掉期间面板自动退化为**浏览器本地词库**模式，tag 勾选 / 随机池 / 权重 / 翻译 /
  导入导出（文件下载与本地解析）照常可用，**节点执行完全不受影响**；
* 也可以用环境变量 `PROMPT_TAG_HTTP=0`（或 `1`）强制开关后重启 ComfyUI；
* 状态保存在 `ComfyUI/user/prompt_tag_manager/.settings.json`。

## 四、节点输入 / 输出

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `tag_config` | STRING | 自动 | **隐藏控件**，保存「词库名 + 已选 tag + 随机池」的 JSON，由面板自动写入，一般不用手动改 |
| `manual_mode` | COMBO | 两者结合（提示词框在前） | 提示词框与 TAG 词库怎么组合，见下表 |
| `manual_prompt` | STRING（多行） | 空 | **提示词框**：手动写提示词，支持 `(tag:1.2)` 权重语法与换行；面板里也有同一个框，两边实时同步 |
| `manual_space_as_sep` | BOOLEAN | 关 | **空格转连接符**：把提示词框里 tag 之间空格/换行换成 `separator`（`1girl solo long_hair` → `1girl, solo, long_hair`）。默认关闭，因为开了会把 `best quality` 这类多词 tag 拆成两个 |
| `natural_prompt` | STRING（多行） | 空 | **自然语言描述框**：写整句人话（如 `a girl standing in the rain, cinematic lighting`）。不会被空格拆分、不会去重、不吃下划线转换 |
| `natural_append` | BOOLEAN | 关 | **组合在末尾**：是否把自然语言描述接到 tag 末尾。关掉时这段文字完全不参与输出（方便临时禁用） |
| `seed` | INT | 0 | 随机池抽样种子，相同种子结果可复现；生成后控制使用 ComfyUI 自带的 `control_after_generate` |
| `separator` | STRING | `, ` | tag 连接符（也用于把提示词框与 tag 拼起来），支持 `\n` 换行 |
| `dedupe` | BOOLEAN | True | 相同 tag（忽略大小写）只保留第一次出现 |
| `underscore_to_space` | BOOLEAN | True | `red_hair` → `red hair`（只作用于 TAG 词库部分，提示词框里的内容原样保留） |
| `weight_style` | COMBO | `不输出权重` | 权重语法：`不输出权重` / `(tag:1.2)` / `tag:1.2` |
| `prompt_preview` | STRING | 自动 | 只读预览，方便看效果，**不参与输出** |

提示词框的四种用法：

| `manual_mode` | 输出 |
| --- | --- |
| 两者结合（提示词框在前） | `提示词框内容` + 连接符 + `TAG 结果`。适合把质量词/画风写在前面，随机 tag 跟在后面 |
| 两者结合（提示词框在后） | `TAG 结果` + 连接符 + `提示词框内容`。适合随机 tag 打底、再补手写限定 |
| 仅使用提示词框 | 只用提示词框，TAG 词库完全不参与（「标签列表」输出为空），此时只靠 `seed` 之外的东西也没关系 |
| 仅使用 TAG 词库 | 只用面板里勾选/随机出来的 tag，提示词框被忽略 |

两者结合时，哪一边为空就只输出另一边，不会多出孤零零的连接符（比如只写提示词、一个 tag 都没选，输出就是提示词本身）。

> 用 **「汐皮笑脸的tag历史板」** 时，在历史面板里单击一条记录，
> 就会把这条提示词**直接写进这里的提示词框（`manual_prompt`）**，打开着的 TAG 面板会立刻同步；
> 它只改提示词框，不动已选 tag、随机池和 `manual_mode`。取消选中时只清掉注入进去的那份内容，
> 你自己手写（或注入后又改过）的不会被误删。
> 注意 `manual_mode` 选「仅使用 TAG 词库」时提示词框不参与输出，注入的文字也就不会生效。

自然语言框接在正文末尾：

```
正文 + [自然语言（若开启）]
正文 = 手动提示词框 ⊕ TAG 词库结果   （按 manual_mode 组合）
```

也可以完全不组合（`natural_append` 关掉），这时自然语言框就当草稿纸用，不参与输出。

> 每个参数在 ComfyUI 里都有悬停提示（鼠标停在参数名上即可看到说明），
> 包括「去重」「下划线转空格」这些开关的作用范围。

**粘贴的提示词带逗号也不会多出逗号**：提示词框/自然语言框里结尾的 `, `、中间连写的 `,,` / `, ,`
都会自动收敛（`a, b, ` + tag → `a, b, tag`，而不是 `a, b, , tag`）。
面板里还有 **整理 / 去重 / 删末尾 / 清空** 四个按钮，方便直接删减提示词框的内容。

**提示词框下面的分段条**：内容按连接符切成一段段胶囊，每段后面跟着它在当前词库里的中文翻译
（`long hair`、`long_hair`、`(long_hair:1.2)` 三种写法都能查到），点段尾的 **✕** 就删掉那一段，
**点译文就能直接改并保存到本地**，右侧徽标显示「翻译 N/M」告诉你多少段查到了翻译。
查不到通常是自然语言长句（词库里没有对应条目），这时它就是原样进入提示词，不影响输出。

### 翻译接口（默认免费、无需 Key）

分段条上有 **「翻译缺失段（N）」** 和 **⚙ 翻译设置** 两个按钮：

* 点「翻译缺失段」→ 只把**词库里查不到**的段发给翻译接口，返回的译文用**橙色**显示并标 `机翻 N`，
  仅用于看，不会写进词库、也不会进入提示词；
* 点 ⚙ 可以选服务、源/目标语言、填地址或 Key，并**当场测试**（失败会显示原因）。

| 服务 | 是否需要 Key | 说明 |
| --- | --- | --- |
| **MyMemory**（默认） | 不要 | 匿名有每日额度，够日常用；实测 0.8 秒返回 |
| Google 免费接口 | 不要 | 质量好，但需要能访问 `translate.googleapis.com`（部分地区不通） |
| LibreTranslate | 可选 | 自建或第三方实例，填 `base_url`；自建一般不需要 Key |
| 离线测试 | — | 不联网，直接把原文加标记返回，用来验证界面流程 |

* 首选服务失败时会**自动换另一个免费服务**重试（可在设置里关掉）；
* 译文按「服务 + 源语言 + 目标语言 + 原文」缓存到
  `ComfyUI/user/prompt_tag_manager/.translate_cache.json`，同样的内容不会重复请求；
* 翻译走的是**后端**（Python 直连），所以不会有浏览器跨域问题；但需要 **HTTP 接口开着**
  （默认就是开的）。

### 译文能改、也能存到本地

分段条上的译文不只是展示，**点一下就改**：

* **点任意一段的译文**（双击整段也行）→ 弹出编辑框，里面已经填好当前译文，改完点「确定」；
  留空确定 = 删掉这条译文；
* 存到哪里，看这段是不是词库里的 tag：
  * **是词库里的 tag** → 直接写回词库的 `descs`（跟词库文件一起存盘，重开面板/换机器都还在，
    左下角的「翻译 N/M」立刻更新）；
  * **不是词库里的**（手写词、自然语言长句）→ 存进本地自定义翻译
    `ComfyUI/user/prompt_tag_manager/.custom_descs.json`，**绿色**显示并标「本地 N」；
* 机翻（橙色）也能直接点开改，改完同样落到上面两个地方之一；
* 机翻比较多时，点分段条上的 **「保存译文」** 一次性全存下来（词库里有的写回词库，
  其余进自定义翻译），省得一条条点；
* 自定义翻译是**独立文件**，不写进词库、不占工作流、也不影响你导入导出的词库文件——
  换词库时它照旧生效（同一个 tag 在任何词库里都能用上你改过的译文）。

### 汐皮笑脸的tag合并（多路提示词）

提示词分散在好几个节点时，用它在前面汇总，再接给 `CLIP Text Encode` 或「汐皮笑脸的tag历史板」：

```
[画风文本] ──prompt_1──┐
[角色文本] ──prompt_2──┼──▶ 汐皮笑脸的tag合并 ──提示词──▶ 汐皮笑脸的tag历史板 ──▶ CLIP
[服装文本] ──prompt_3──┘
```

| 参数 | 说明 |
| --- | --- |
| `prompt_1` / `prompt_2` … | 每路提示词，按序号顺序拼接；接满最后一个口会自动多出一个空口 |
| `separator` | 各段之间的分隔符，默认 `, `；`\n` = 换行，`\t` = 制表符 |
| `dedupe` | 打开时按逗号 / 换行把各路拆成 tag，完全相同的 tag（忽略大小写）只保留第一次出现的位置 |

- 节点上还有一个 **「＋ 增加输入端」** 按钮：想提前多留几路、或者自动加口没出现时，
  点一下就会新增一路 `prompt_N`；断开连线后空口会保留，不会突然消失。
- 空段自动跳过，每段首尾空白会自动去掉；输出只有一路 `提示词`（STRING）。

### 汐皮笑脸的tag历史板

历史板接收最终提示词并原样保存，面板里可以按 **文字 / 图文** 两种模式看历史：

* **输入**：`prompt` 接合并后的提示词（也可以直接接任意 STRING 节点）；
* **输出**：`提示词`，默认透传输入；在面板里选中某条历史后，输出改成那条历史，
  这样这次排队就能直接用旧提示词；
* 节点上的 `follow_panel` 可切换「跟随面板选中 / 只透传工作流文本」；
* 节点上的 **📋 打开历史Tag生成面板** 按钮，或顶栏（运行 / 队列 那一排）的 **提示词历史** 按钮都会弹出
  **独立窗口**（不再占用侧边栏）：窗口可以拖动、右下角缩放、点「–」收起到标题栏，
  位置和大小会记住，关掉再开还是原样；Ctrl+K 命令面板里搜「提示词历史」也能打开；
* 面板支持单条 / 批量删除、复制、收藏夹、就地编辑、拖拽排序、搜索、
  手动添加、导入导出；图文模式会显示这次生成的图片 / 视频缩略图；
* **搜索高亮**：搜索框里输入关键词后，命中的词会在提示词正文里**用暖色底标出来**
  （不区分大小写、保留原文大小写），同时正文自动展开，保证命中位置一定看得见；
  双击看大图时的大图预览里同样高亮；
* **导入到词库**：每条记录右侧的 **导入词库** 按钮会弹出小窗口，可以选词库、填一级 / 二级分类，
  再决定「整条提示词作为一条」（默认）还是「按逗号 / 换行拆成一个个 tag」写进词库。
  默认一级分类「提示词历史」、二级分类「导入」，词库里已有的 tag 会自动跳过；
  导入后如果 Tag词库面板正开着同一个词库，会自动刷新看到新 tag；
* **图文模式默认只看图片**：按窗口宽度自动排成 3～4 列的图片墙，缩略图等高、按原比例完整显示、
  不裁切、不留黑边；卡片右下角的收藏 / 复制 / 删除按钮鼠标移上去才出现。点模式按钮旁的
  **「显示文字」** 后，图片按原比例贴在左侧、提示词紧跟在右（不再堆在图片下面），再点「隐藏文字」收起。
  每次重新进入图文模式都会回到只看图片；
* **收藏夹**：每条右侧点 ☆ 收藏后，点工具栏的 **「☆ 收藏夹」** 就只看收藏的记录，
  再点一次回到全部列表；收藏夹独立显示，不会把新生成的记录挤到列表底部；
  在「全部」里点全选**不会勾选收藏记录**，收藏记录只有在收藏夹里才能被全选；
* **分页**：记录多时只渲染当前页，默认每页 20 条；底部可以切每页 20 / 50 / 100 条、
  跳页码、首页 / 上一页 / 下一页 / 末页。分页后「全选」只选本页，勾选状态会保留，
  批量删除 / 复制 / 导出可以跨页处理；
* **双击看大图**：图文模式下双击缩略图打开大图 / 播放视频，Esc 或右上角 ✕ 关闭；
* **双击编辑**：文字模式下鼠标左键双击正文（或点 ✎）进入编辑；编辑框会按内容自适应，
  但最高约 260px / 36vh，长提示词在框内滚动，不会把整张卡片拉得过长；
* 只保存**正向提示词**，不保存反向提示词；提交时抓不到完整文本会等执行期再校正。

把历史板里选中的记录写回「汐皮笑脸的随机tag」的手动提示词框，也是支持的：
打开面板顶部的「选中即注入工作流」，单击历史记录即可，TAG 面板会同步刷新。

历史数据位置：

```
ComfyUI/user/prompt_history/
├── history.json          # 全部记录 + 面板设置 + 当前选中项
└── images/               # 出图副本 + 缩略图（删除记录时一并清理）
```

## 五、批量导入格式

点面板上的 **📥 导入**，选文件或直接粘贴，支持以下写法（会自动识别）：

**1. CSV / TSV（最常用）**

```csv
一级分类,二级分类,子项
人物,发色,red_hair
人物,发色,blue_hair,蓝发
场景,自然环境,forest
```

* 首行如果是表头（`一级分类,二级分类,子项` 之类）会自动跳过；
* **第 4 列可选**，填中文描述（有描述时导出也会带上第 4 列）；
* 两列 → 第一列当一级分类，tag 归到「默认」二级分类；
* 一列 → 全部 tag 进「未分类 / 默认」；
* 分隔符支持 `,` `，` `\t` `|` `::` `>` ` / `。

**2. TXT（标题风格，可读性最好）**

```text
# 人物
## 发色
red_hair
blue_hair
## 眼睛
blue_eyes
# 场景
forest
```

**3. JSON**

```json
{
  "name": "我的词库",
  "groups": [
    {
      "name": "人物",
      "subs": [
        { "name": "发色", "tags": ["red_hair", "blue_hair"], "descs": { "red_hair": "红发" } }
      ]
    }
  ]
}
```

同时也接受这些简写：`{"人物":{"发色":["red_hair"]}}`、`[{"group":"人物","sub":"发色","tag":"red_hair"}]`、
`["tag1","tag2"]`、`[{"text":"red_hair","desc":"红发"}]`。

**4. SQL（WeiLin-Comfyui-Tools 导出的词库）**

面板里直接选 `.sql` 文件即可，无需手工转换。支持
`tag_groups` / `tag_subgroups` / `tag_tags` 三张表的 `INSERT` 语句，
自动按 uuid 关系拼成三级分类，`desc` 字段会变成中文描述，并按 `create_time` 还原顺序。

也可以在命令行批量转换（适合一次导入很多份、或想直接生成内置词库）：

```bash
# 单个文件 → builtin_tags/renwu.json
python tools/weilin_sql_to_json.py "D:/tags/人物_export.sql" --name 人物 --filename renwu

# 整个目录（每个 .sql 一份词库）
python tools/weilin_sql_to_json.py "D:/tags" -o builtin_tags

# 目录里所有 .sql 合并成一份
python tools/weilin_sql_to_json.py "D:/tags" --merge --name 全部词库

# 直接写进 ComfyUI 的用户词库目录
python tools/weilin_sql_to_json.py "D:/tags" --out-dir "D:/ComfyUI/user/prompt_tag_manager"
```

**导入方式**（弹窗里可选）：

* **合并到当前词库**（推荐）：已有一级/二级分类会合并，tag 自动去重，描述取先出现的；
* **覆盖当前词库**：直接用文件内容替换；
* **保存为新词库**：不动现有词库。

## 六、词库文件与数据位置

词库是可读可编辑的 JSON，放在：

```
ComfyUI/user/prompt_tag_manager/*.json     ← 你自己的词库（可直接拷给朋友）
ComfyUI/user/prompt_tag_manager/.custom_descs.json   ← 你手改/保存的「本地自定义翻译」
ComfyUI/user/prompt_tag_manager/.translate_cache.json ← 机翻缓存（可随时删）
ComfyUI/custom_nodes/ComfyUI-PromptTagManager/builtin_tags/*.json   ← 内置词库（可直接改）
```

以 `.` 开头的文件不会被当成词库列出来；删掉它们只是丢掉对应的译文/缓存，不影响词库本身。

内置词库：

| 文件 | 词库名 | 规模 | 中文翻译 | 说明 |
| --- | --- | --- | --- | --- |
| `renwu.json` | 人物 | 1 一级 / 28 二级 / **1612 tag** | 1612 / 1612 | 由 WeiLin 导出的 SQL 转换而来，**默认词库** |
| `danbooru_basic.json` | Danbooru 基础 | 12 / 48 / 573 tag | 573 / 573 | 通用质量词、画风、场景、构图等 |
| `chinese_style.json` | 国风古风 | 8 / 24 / 244 tag | 244 / 244 | 汉服、国风画风、器物、氛围 |
| `yijian-01…11.json` | 一键模式-01…11 | 每份约 20 个二级 / 2 万条 | 用自带的中文备注 | **整句提示词预设库**，见下方说明 |

### 关于「一键模式」预置词库（20 万条整句提示词）

这 11 份来自 WeiLin 的「一键模式」导出：每个二级分类（一键NSFW-01…203）里是约 1000 条
**完整提示词**（一条就是 30~50 个 tag 的整句，如 `1girl, breasts, solo, ...`）。
用法和普通 tag 库不同：

1. 下拉选 `一键模式-01`，中栏选一个二级分类；
2. 点中栏那一行的 **🎲**，把它设成随机池（默认抽 1 条）；
3. 执行 → 每次从这 1000 条里随机出一条完整提示词，拼到输出里。

也可以直接在右栏点某一条预设，把它当固定提示词用（顺序可以用「⇅ 反转」和拖拽调整）。
注意：这些「tag」本身很长，面板会截断显示，鼠标悬停可看全文。

> 这 11 份合计约 153 MB。如果不需要，直接删掉 `builtin_tags/yijian-*.json` 即可，
> 插件其余功能完全不受影响（`builtin_tags/.ptm_index.json` 是统计缓存，会自动重建）。

* 默认词库由 `tag_store.py` 的 `DEFAULT_LIBRARY_NAME = "renwu"` 决定，可用环境变量
  `PROMPT_TAG_DEFAULT_LIBRARY=danbooru_basic` 覆盖；
* **没有「只读保护」**：词库在哪就在哪改。修改内置词库（如「人物」「一键模式-01」）会直接写进
  `builtin_tags/*.json`，改完即时生效，不会另存副本、也不会多出 `xxx (用户)` 这种词库；
  重命名 / 删除同样对内置词库有效。
  唯一的代价是：**插件升级或重新覆盖安装时，这些文件会被新版替换**。
  所以如果你有一份改了很久、很珍贵的词库，建议点「＋新建」建一个自己的词库（存在
  `ComfyUI/user/prompt_tag_manager/`），重要内容放那里更稳妥；
* 想换用户词库的存放位置可以设环境变量 `PROMPT_TAG_USER_DIR=/path/to/dir`；
* 词库是纯文本，建议用 git 或网盘备份，也可以手工编辑；
* 新增 tag 后想补中文翻译：`python tools/fill_descs.py --report` 看缺哪些，
  `python tools/fill_descs.py --map 翻译.json` 合并回去。

## 七、常见问题

**Q：面板没弹出来 / 节点上没有按钮？**
强制刷新页面（Ctrl+F5）。前端资源路径依赖插件文件夹名，改名后请确保目录名与 `__init__.py` 同级结构未变。

**Q：改了 tag 但输出没变？**
本节点声明了「每次执行都重新运行」（返回 `IS_CHANGED = NaN`），不会命中缓存；如果仍未变，确认连接的是「提示词」输出而不是旧连线。

**Q：随机结果每次都不一样，但我想固定？**
把 `seed` 的生成方式设为 `fixed`。随机池的抽样完全由 seed 决定，同 seed 结果稳定。

**Q：面板显示「本地模式」？**
一般是 HTTP 接口被关掉了（点提示条里的「开启 HTTP 接口」即可恢复），
或 `/prompt_tag/*` 没注册成功（少见）。此时词库退化为浏览器 `localStorage`，
tag 功能照常可用，但词库存不到磁盘。

**Q：ComfyUI 无法自动保存工作流了？**
先看浏览器控制台有没有 `QuotaExceededError`。ComfyUI 的工作流与自动存档都写浏览器
localStorage（通常 5MB 上限），写满就会保存失败。本插件现在做了五重保护：

1. **随机池只存引用**：池里只记「词库 / 一级分类 / 二级分类」+ 候选数量（约 190 字节），
   候选在节点执行时才由后端从磁盘读。旧做法是内嵌候选，一个池就 350 KB 起、
   三个池 1 MB+ —— 这是主因，已修复（同配置体积缩小约 3300 倍）；
2. **老工作流自动瘦身**：用旧版存过的工作流，只要在面板里打开过一次，
   内嵌的候选就会自动换成引用，再保存时体积立刻回落；
3. **启动时自动清理旧缓存**：旧版在「本地模式」下写进 localStorage 的词库，
   超过 512KB 会在启动时自动清掉（服务端模式直接删除，本地模式瘦身到示例词库），
   控制台会打印「已清理 XX KB」，面板也会提示一次；
4. **本地词库 3MB 上限**：超了明确报错并建议改用磁盘词库，绝不硬写撑爆存储；
5. **节点里的预览/记录限长**（1200/400 字），配置超 32KB 时控制台警告。

如果仍有问题，可以在浏览器 DevTools 里执行 `localStorage.clear()`（会清掉 ComfyUI 的界面偏好，
但工作流文件不受影响），再打开工作流保存一次。

**Q：升级后老工作流报 `AttributeError: 'bool' object has no attribute 'replace'`？**
这是 1.0.1 及更早版本的 bug：新参数被插进了控件列表中间，而 ComfyUI 加载工作流是按
**位置**把 `widgets_values` 填进控件的，于是老工作流的参数整体错位（`separator` 拿到了
`dedupe` 的 `True`）。

* 1.0.2 起参数一律**追加在末尾**，老工作流不会错位；
* 后端对所有参数做了类型兜底，就算错位也不会让节点执行失败；
* 前端在加载工作流时会自动把错位的控件值**修回默认值**（控制台会打印
  `[PromptTag] 已修复 N 个错位的控件值`）。看到这条提示后，检查一下节点上的参数
  （分隔符、去重、权重语法、提示词框）再保存一次工作流即可。

**Q：一个词库能装多少 tag？**
实测 500+ tag 的面板操作是流畅的；内置的「人物」词库有 1612 个 tag，同样流畅。
导入超大文件时建议按分类拆成多套词库。

**Q：我有一堆 WeiLin 导出的 .sql 词库，怎么用？**
三种方式，按文件大小挑：

1. **小文件（几 MB 以内）**：面板里「📥 导入」直接选 `.sql`；
2. **大文件（几十 ~ 上百 MB）**：「📥 导入」→ 最下面的 **「大文件：直接从服务器磁盘路径导入」**，
   填绝对路径（如 `D:/tags/xxx.sql`），并设置「每库最多 N 个 tag」自动拆分 —— 全程不经过浏览器，
   也就没有 32MB 上传上限和内存问题；
3. **命令行批处理**：
   ```bash
   python tools/weilin_sql_to_json.py "D:/tags/xxx.sql" --name 一键模式 --filename yijian \
          --split-by-tags 20000 -o builtin_tags
   ```
   `.sql` 是流式解析（119MB / 20 万条约 20 秒），拆好的 JSON 直接就是可用词库。

**Q：超大词库（几十万 tag）面板会不会卡？**
不会。面板做了三层保护：标签列表一次最多渲染 400 个（超出显示「还有 N 个未显示」按钮）、
搜索有 220ms 防抖且结果上限 2000 条、词库数量统计走 `.ptm_index.json` 缓存
（否则每次打开面板都要重读几十 MB）。实测 2 万条的预置库加载与浏览都正常。

**Q：默认词库不是我想要的？**
默认词库由 `tag_store.py` 里的 `DEFAULT_LIBRARY_NAME = "renwu"`（内置「人物」词库）决定，
也可以设环境变量 `PROMPT_TAG_DEFAULT_LIBRARY=danbooru_basic` 覆盖，不用改代码。
面板会记住你上次用的词库，下次打开新节点直接就是它。
注意：节点已经保存过的词库名存在工作流里，换默认不会影响老工作流。

**Q：导入的 tag 会不会丢？**
不会。导入走的是「先把你没保存的修改落盘 → 再读磁盘合并 → 写回」，并且保存操作是串行排队的，
不会出现「自动保存把导入结果盖掉」的情况；导入既是立即写盘，关掉面板/重开/重载工作流都在。
面板顶部的胶囊会显示「已保存 / 待保存…」，异常时变红并提示。

**Q：改了内置词库，原始文件会被覆盖吗？**
会。插件**不做只读保护**：词库在哪就在哪改，改内置词库就是直接改 `builtin_tags/*.json`，
不产生副本、不改词库名，重命名和删除也一样生效。
代价是插件升级/覆盖安装时这些文件会被新版替换——重要内容建议另建一个自己的词库保存。
（测试脚本会把内置词库复制到临时目录再跑，不会动到仓库里的文件。）

**Q：tag 上没有中文？**
先确认右上角开关是「中 已开」（关掉则只看英文 tag）。

**Q：中文翻译不对/我想自己改？**
四种方式：

* 单个改：把鼠标移到那一行，点右侧 **✎**（或直接双击翻译文字）→ 输入新的翻译 → 确定；
  留空确定就是删除翻译；
* 提示词框里的段：直接在**分段条上点那段译文**（机翻的橙色译文也可以）→ 改完确定。
  是词库里的 tag 就写回词库，不是就存进 `.custom_descs.json`；
* 批量改：中栏二级分类那一行点 **≡「批量编辑」**，每行写成 `tag = 中文翻译`
  （不带 `= ` 的行就是纯 tag，翻译会被清掉）；
* 文件改：直接编辑 `ComfyUI/user/prompt_tag_manager/*.json` 里的 `descs` 字段，
  格式是 `"descs": {"red_hair": "红发"}`；自定义翻译则在 `.custom_descs.json` 里，
  格式是 `{"原文": "译文"}`。

改内置词库会直接改内置文件（没有只读保护）。

若某个 tag 是新建的，它自然还没有翻译——
用 `python tools/fill_descs.py --report` 可以看到缺哪些，补进 JSON 的 `descs` 即可。

## 八、测试

仓库自带四套测试（不参与运行时，可整目录删除 `tests/`）：

```bash
# 1) 后端逻辑（词库解析/导入导出/提示词构建/节点函数/SQL 解析）
python tests/run_tests.py

# 2) 前端纯逻辑（与后端行为对齐）
node tests/run_js_tests.mjs

python tests/e2e_server.py &

```

界面测试用 jsdom 驱动真实的编辑器，并通过真实 HTTP 调用 Python 接口，
覆盖导入导出（含 `.sql`）、随机池、权重、中文翻译显示与中文搜索、词库 CRUD、
**导入后关闭再重开不丢数据**、浮窗、离线降级等 380+ 条断言。

后端测试还覆盖整合后的节点映射：三个节点都归入 `提示词管理` 分类、
显示名正确、简易版已删除，以及 `PromptHistoryMerge` 的顺序拼接和 `/prompt_history` 接口前缀。

其中「导入后重开」是一组专门的回归用例：合并导入内置词库、编辑后立刻导入（与自动保存竞争）、
存为新词库、词库被删除后重开，四种路径都要求数据零丢失。

## 九、与 WeiLin-Comfyui-Tools 的差异

| 项目 | WeiLin | 本项目 |
| --- | --- | --- |
| LoRA 管理 | 有 | **无**（只做 tag） |
| 词库存储 | SQLite | **JSON 文本**（易备份、易手改、易分享） |
| 前端 | Vue + Vite 构建产物 | **原生 JS，无构建步骤** |
| 依赖 | 若干 pip 包 | **零第三方依赖** |
| 面板形态 | 悬浮球 + 窗口 | 节点按钮 + 可拖拽缩放浮窗 |
| 随机抽取 | 有 | 有（按二级分类设随机池 + N，seed 可复现） |
| 批量导入导出 | 有 | 有（JSON / CSV / TSV / TXT / **它的 .sql 导出可直接导入**） |
| 中文描述 | 有 | 有（悬停提示 + 中文搜索命中） |

> 也就是说：WeiLin 里导出的 tag sql 可以直接喂给本插件，反过来本插件导出的
> CSV（`一级,二级,子项,描述`）也能被 Excel 直接打开编辑。
